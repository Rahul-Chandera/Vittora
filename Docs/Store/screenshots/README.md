# App Store screenshots

Everything here is regenerated by script. Don't hand-shoot replacements — the
captures are reproducible, and a hand-shot one drifts from the rest.

```bash
# iPhone / iPad, one set per locale
Scripts/store/capture_screenshots.sh iphone-69    "iPhone 17 Pro Max"
Scripts/store/capture_screenshots.sh iphone-69-in "iPhone 17 Pro Max" en en_IN IN
Scripts/store/capture_screenshots.sh iphone-69-hi "iPhone 17 Pro Max" hi hi_IN IN
Scripts/store/capture_screenshots.sh iphone-69-es "iPhone 17 Pro Max" es es_MX US
Scripts/store/capture_screenshots.sh ipad-13      "iPad Pro 13-inch (M5)"

Scripts/store/capture_watch_screenshots.sh      # needs a paired iPhone+Watch sim
Scripts/store/capture_mac_screenshots.sh        # runs the real Mac app, see below

python3 Scripts/store/make_marketing.py         # frame + headline -> marketing/
```

`ONLY=04-fiftythirtytwenty` re-shoots a single slot. `KEEP_DEVICE=1` skips the
device erase (faster, but the previous locale and data survive — only for
debugging). `DEMO_MONTHS` defaults to 12.

## How it works

No production code exists to serve screenshots. The scripts reuse flags the app
already had for UI testing:

| flag | effect |
|---|---|
| `--uitesting --ui-test-seed-demo` | seed the showcase dataset |
| `UITEST_DEMO_REGION=US\|IN` | currency and payee set |
| `UITEST_DEMO_MONTHS=12` | a year of history instead of two months |
| `UITEST_INITIAL_TAB=<AppTab>` | open straight to a tab, no tapping |
| `--ui-test-open-url=vittora://…` | apply any deep-link route at launch |

Two of those were added for this pipeline: `UITEST_DEMO_MONTHS` (Year in Review
with two bars undersells it) and `--ui-test-open-url`.

**Use `--ui-test-open-url`, never `simctl openurl`.** SpringBoard puts an
`Open in "Vittora"?` alert on screen for an external URL open, and that alert
lands in the middle of the capture.

**Every set erases its device first.** SpringBoard state outlives the app: a
stray system alert, a previous locale, or a half-seeded store survives
terminate-and-relaunch.

## Gallery slots

`01-dashboard`, `02-transactions`, `03-budgets`, `04-fiftythirtytwenty`,
`05-reports`, `06-yearinreview`.

**Savings is deliberately not in the gallery.** `AppTabView` routes overflow tabs
(savings, debt, splits, tax, settings) to the More hub root by design — see the
`ponytail:` note at `AppTabView.swift:196` — so a capture would show a menu under
a "savings goals" headline. 50/30/20 deep-links properly and is also a 1.4
feature worth advertising. The Description still covers savings goals in words.
The `mac` set keeps its older `04-savings` raw because it cannot be re-shot yet.

## Headline text goes through CoreText, not Pillow

`make_marketing.py` renders headlines via `Scripts/store/render_text.swift`.
Pillow here is built without Raqm, so it cannot shape complex scripts — Devanagari
matras and conjuncts come out in the wrong order. Strings are rendered once at
`BASE_PT` and scaled per canvas, so the whole run is one `swift` invocation.

### hi / es are only partly localized

Slots 01–03 are fully localized and publishable. Slots 04, 05 and 06 show English
UI strings because **64 keys are missing from `Localizable.xcstrings`** across
50/30/20 (G1), Emergency Fund (G2) and Year in Review (W1) — those screens were
built without their strings being extracted, so hi and es fall back to English.
G1 and G2 shipped in **1.4.0, already live**, so Hindi users see this today.

Until those keys land, either publish a 3-shot hi/es gallery or leave the
localized listings on the English gallery. Also note the India demo dataset uses
English payee names and notes ("Lunch Order", "Monthly Staples"); those are user
data rather than UI strings, but a Hindi set would read better with Hindi ones.

### Mac captures are blocked on this machine

`capture_mac_screenshots.sh` is complete and correct, but the Mac app launches
without ever creating a window while the screen is locked — startup reads the
login keychain, which is locked too. Nothing is logged and no window appears, so
`screencapture -l` has nothing to target. Run it with the machine unlocked and
the existing v1.0-era `mac/` raws will be replaced in one command. A signed build
is required (`CODE_SIGNING_ALLOWED=NO`, as `make build-macos` uses, produces a
binary whose entitlements don't apply).

Mac accepted sizes are 1280x800, 1440x900, 2560x1600 and 2880x1800 — the current
1440x900 is valid, just low-resolution.

## Watch

The watch app has no data of its own; `WatchSnapshotStore` is fed over
WatchConnectivity by the phone. The script boots a *paired* iPhone + Watch, seeds
the phone, and only then captures — a standalone watch sim shows either empty
state or a stale cached snapshot ("Updated 2 days ago"), which is why the watch
device is erased too. `simctl status_bar` does not apply to watchOS, so the watch
clock is whatever the host reads, not 9:41.
