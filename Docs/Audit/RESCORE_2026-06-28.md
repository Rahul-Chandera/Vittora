## 4. Conditions

### Met for the closed beta
NO-GO blockers (§1) ✅. Green CI ✅. Recommend also: **enable the required-status-check branch protection** in GitHub settings (documented in `BRANCH_PROTECTION.md` but a repo-admin action, not enforced by the file).

### Must clear before **public App Store launch**
1. **Deployment-target decision (market-reach):** iOS 26 / macOS 26 minimum vs the plan's iOS 18 / macOS 15. Requiring the current-latest OS as the floor sharply limits addressable devices (esp. Mac). Confirm intentional; this is the single biggest open *business* input.
2. **Real-device / macOS-host verification (TESTING-4):** CI runs on the iOS simulator, so the on-device **Secure-Enclave** path and **macOS-host** paths (`#if os(macOS)` file-protection, sandbox) are unexercised. Run a signed device + macOS-26 pass (self-hosted runner / Xcode Cloud) before shipping.
3. **Deployment-target inconsistency:** test targets `26.4` vs app `26.0` — align to `26.0` (CI on the 26.5 sim currently masks this).
4. **Tax accuracy (A13, Medium):** confirm/fix the surcharge **marginal relief computed pre-cess** (current model caps final-incl-cess, understating ~4% of the relief at boundaries) and re-validate vectors against an official calculator.
5. **Accessibility Low items (E2–E6 remainder):** `VActionButton` 44pt hit target, `VSearchBar`/`CategoryFormView` labels, `TagInputView` targets, fuller `.isHeader` coverage.
6. **App Store metadata (D5):** scope description/screenshots to *shipped* features (no Watch/Widgets/Siri/Vision).
7. **P1 engineering epics:** **G** (code quality — shared CurrencyFormatter, key constants), **H** (performance — pagination, predicate pushdown, search debounce, drop 500 caps), **I** (architecture — Swift 6 mode, non-optional DI, replace global refresh counter), **J** (iPad/macOS adaptivity, extract Core for future widget/watch targets).
8. **Broaden UITest coverage** beyond onboarding; add the trims (`fetch` UIBackgroundMode, macOS photos-library entitlement if unused).

### Strategic (pre-scale, from the original Business analysis — unchanged)
- Single Wave-1 market (don't parallelize US+India); correct UVP/metadata to shipped scope; externalize tax rules; rebuild KPIs bottom-up after a soft launch; build the splitting invite loop before claiming a viral moat.

## 5. Bottom line

Vittora has moved from an **un-shippable** state (data-corrupting, MVP-incomplete, App-Store-rejecting) to a **beta-ready, CI-gated** one. The remediation was disciplined: atomic ledger writes, a real security model, a working notification engine, App-Store-compliant configuration, app-wide Dynamic Type, and a green CI gate that finally exercises the UI tests.

**Recommendation: GO WITH CONDITIONS for a closed TestFlight beta now.** Hold public App Store launch until §4's "before public launch" conditions clear — principally the deployment-target/market-reach decision, real-device SE/macOS verification, the P1 quality/perf/architecture epics, and the strategic GTM calls that were the audit's other half and remain unaddressed.

*The financial-integrity, security, compliance, accessibility, and testing dimensions are now genuinely strong. The remaining risk is concentrated in strategy/market and in the P1 engineering polish — not in correctness or safety.*
